## Medium

### 9. `getblocktemplate` reports LWMA activation using previous-block semantics

- **Path:** `src/rpc/mining.cpp`
- **Line:** 871
- **Severity:** medium
- **Category:** Diff
- **Description:** `getblocktemplate` checks `DeploymentActiveAt(*pindexPrev, ...)` for LWMA, but GBT rules describe the next block template. At activation height, the previous block is not active yet, so miners will miss the required `!lwma` rule exactly when the next block starts using LWMA difficulty.
- **Suggested fix:** Use `DeploymentActiveAfter(pindexPrev, consensusParams, Consensus::DEPLOYMENT_LWMA, ...)`, matching the next-block semantics used elsewhere in mining RPC code.

### 10. `signp2mrtransaction` can mark unsatisfied script-path spends complete

- **Path:** `src/wallet/rpc/p2mr.cpp`
- **Line:** 516
- **Severity:** medium
- **Category:** Diff
- **Description:** `signp2mrtransaction` falls back to a witness stack containing only `script` and `control_block`, then marks the input complete. That is only valid for trivial scripts such as `OP_TRUE`; non-trivial leaves requiring witness arguments or signatures can be returned with `"complete": true` while still being invalid.
- **Suggested fix:** Do not set `fallback_complete = true` unless the constructed witness is actually satisfiable. Prefer removing this fallback, requiring explicit witness args for non-miniscript leaves, or validating the finalized input before reporting completion.
